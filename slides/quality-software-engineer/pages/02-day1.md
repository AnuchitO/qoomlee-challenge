<div class="qse-eyebrow">DAY 1 · DEVELOP</div>

# Develop: twin-track

<span class="qse-pill-sdet">SDET primary</span> <span class="qse-pill-qe">QE reviews acceptance criteria</span>

<div class="mt-3 text-sm">
A <b>commit</b> = one saved snapshot of changes. A <b>PR</b> (pull request) = asking to merge it in — like the one below. Code + automated test, written together, every time — not "code first, test later" (the old QA pattern where bugs accumulate).
</div>

```bash
# same commit, same PR
feat: add cancel order with tests
  handler:  PUT /api/orders/:id/cancel
  tests:    state transitions, edge cases, mocked refund call, concurrency
```

<div class="text-xs qse-text-muted mt-1">"feat:" = a commit-message label meaning "new feature". "PUT /api/…" = the web address this code responds to. "Concurrency" test = checking two requests racing each other.</div>

<div class="qse-card mt-2 text-sm">
<b>Mindset:</b> Collaboration over Silos — dev and QSE aren't separate phases, they work the same round.
</div>
